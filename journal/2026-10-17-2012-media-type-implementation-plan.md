# Media type: implementation plan and milestone results (2026-10-17 to 2026-10-18)

Moved verbatim from the "Implementation plan" section of `docs/MEDIA_TYPE.md` on 2026-10-19, with links updated for the new location.

Each milestone ends with its exit check on the TCL before the next starts. Commands and results go to [device testing](../docs/DEVICE_TESTING.md).

| # | Milestone | Main work | Exit check |
| --- | --- | --- | --- |
| 1 | Catalog v2 and counts (**done 2026-10-17**) | Query and JSON v2 (`videos`, counts, bump `VERSION`); keep the unchanged shortcut safe against v1 files; JVM tests for read/write, v1 rejection, path safety | Refresh builds v2 on the TV; photo counts match v1; video counts match the survey within the snapshot lag; cached read stays under 3 s. **Met:** see [device testing](2026-10-17-2112-catalog-v2-milestone-1.md) |
| 2 | Settings and picker (**done 2026-10-17**) | `media_type` preference, Type row (and the Photos row renamed Media), summary text, card counts and badges per mode, empty-state rules, and the screensaver fallback (pulled forward from milestone 5 because it is a small factory rule); photos-only path unchanged | All settings and picker states in the mock work with the D-pad; the Photos type is today's behavior. **Met:** see [device testing](2026-10-17-2123-settings-and-picker-milestone-2.md). The slide model gaining a kind moves to milestone 4, where video slides first exist |
| 3 | Progressive data source (**done 2026-10-17**) | `ProgressiveReader` with `SmbRemoteVideo` and `ProgressiveMediaDataSource`, gate math, rate memory, cache cleanup; JVM tests with an in-memory share (tail-first, ordering, gate maths, abandonment, cleanup) | On the TV: typical clip starts in under 3 s with no stall; 4K HLG and the 89 Mbps clip start within 5 s of the model and finish with at most one pause; temp files gone afterwards. **Met, with one caveat:** see [device testing](2026-10-17-2204-progressive-reader-milestone-3.md) |
| 4 | Playback in the preview (**done 2026-10-17**) | Video surface in `SlideshowView` sized to the clip, `MediaPlayer` lifecycle, the low-buffer pause and resume safeguard, errors and skip rules, labels from container metadata | Portrait, landscape, rotated and HDR clips upright and correctly proportioned (user check); 20 consecutive clips with stable memory; failure and skip paths exercised. **Met:** see [device testing](2026-10-17-2252-video-playback-in-the-in-app-slideshow-milestone-4.md) |
| 5 | Screensaver fallback (**done 2026-10-18**) | `forDream` flag in `PhotoSourceFactory`; the dream path returns the 500-photo *All* source when Type is not Photos; the settings note under Type | With Type = Photos + Videos and Type = Videos, idle activation shows 500 random photos and ignores saved albums while honoring Interval and Label; with Type = Photos behavior is unchanged (albums respected); the dream never touches video code or the video list. **Met:** the real idle-timeout activation was observed; see [device testing](2026-10-18-0837-screensaver-idle-activation-milestone-5.md) |
| 6 | Videos type and covers (**done 2026-10-17**) | Type *Videos*, Media *All* with proportional videos (built in milestone 4), poster-frame covers | Each Type in the in-app slideshow; covers cached and persistent. **Met:** see [device testing](2026-10-18-0824-poster-covers-milestone-6.md) |
| 7 | Hardening (**done 2026-10-18**) | Recorded logs per clip (phase timings, no names), a 60-minute soak, album-start and low-storage fixes, a cap on how far small clips are enlarged, docs | Docs and roadmap updated; open questions closed or recorded. **Met:** see [device testing](2026-10-18-0959-hardening-milestone-7.md) |

Optional later: fetching the next clip's head during playback of a light clip, a rolling cache window for the few clips over the free-space limit, an audio toggle, HDR tuning.
