# Android TV client check (2026-10-12)

Moved verbatim from `docs/PHOTO_SOURCES.md` on 2026-10-19, with links updated for the new location. Inline corrections and updates are kept as originally written.

The read-only Android adapter uses SMBJ 0.15.0 with its explicit Guest authentication mode. Initial TV tests failed during SMB session setup with `SMB2GuestSigningRequiredException`; they did not reach share listing or image reads. SMBJ refuses a Guest session when the server advertises message signing as required. This matches [SMBJ issue 554](https://github.com/hierynomus/smbj/issues/554), which reports the same Guest/signing incompatibility with a macOS file server. The 0.15.0 source retains this check. Enabling SMBJ's multi-protocol negotiate option alone did not change the TV result. The issue tracker suggests combining that option with `withSigningRequired(false)`; testing that exact combination on the TV still failed with the same exception. Restricting the Android client to SMB 2.0.2/2.1 dialects also failed with the same exception, so that restriction was removed. A separate development-Mac probe with jcifs-ng 2.1.9 also failed authentication, so it is not a validated replacement.

Apple's [SMB troubleshooting note for Macs bound to Open Directory](https://support.apple.com/en-ae/101956) says macOS uses SMB3 by default and documents configuring the SMB server to accept SMB2 only by setting `ProtocolVersionMap` to `2`. The article is specifically about Open Directory binding/authentication problems, which have not been established on this Mac mini; it is not yet a confirmed fix for this Guest-signing failure. SMB2-only also removes SMB3 support and associated security features. An additional community-reported workaround is the macOS server preference `SigningRequired=false` in `/Library/Preferences/SystemConfiguration/com.apple.smb.server`; Apple documents it only in an archived article for older macOS versions; it was later tested and worked (see [the server change](2026-10-12-1729-mac-mini-signing-change.md)). After the server change, the TV successfully listed and read photos during manual preview. Its DreamService started on idle and displayed the first SMB photo. Multi-photo progression and HEIC rendering in dream mode remain to be verified. The bundled sample-photo preview still works after moving source listing and decoding to the background.
