# Photo screensaver product brief

## Goal

Show personal photos on a TCL Google TV as a slideshow. The user can choose which source to show and how long each photo remains visible. The first real source is the Mac mini's Photos library files, read from its existing SMB `Photos` share. The server has been verified to allow read-only SMB Guest access and to reject anonymous SMB access; Google Photos remains a possible later source.

## Core experience

1. Open the TV app with the remote.
2. Choose a photo source. The launcher settings use a compact two-column table for Sample pics or SMB share, **All** or **Choose Albums**, **Type**, pool size, interval, **Layout**, and label. **All** remains the default and preserves the existing random sample behavior. SMB host, share name, and library path are edited on a separate SMB settings screen. Main settings changes remain staged until Save; Cancel restores the saved settings. Opening **Choose Albums** activates album mode; picker selection changes save immediately and the carousel's Done button or remote Back returns to settings. On first album-picker use or explicit refresh, the TV reads a local staged copy of the Photos SQLite database over the read-only SMB share and builds a persistent app-private JSON catalog. Later picker and playback use reads the local catalog. Cover thumbnails also persist in app-private storage across picker visits. Shared Albums remain a later phase. See [album selection](ALBUM_SELECTION.md).
3. Choose the slide interval, random pool size for **All** mode (100, 250, 500, or 1,000), and label mode (place name plus date or no label). The pool choices are disabled in **Choose Albums** mode. When specific albums are selected, the slideshow uses every usable photo in those albums. Place names are best effort; GPS coordinates appear when Android cannot resolve one. Legacy Date-only preference values are unsupported and fall back to the default Location + date mode.
4. Preview the slideshow immediately.

When the SMB source is unreachable, the slideshow keeps retrying with backoff for as long as it runs. After three consecutive failures it shows three stored public-domain artworks with the caption "SMB failure. Loading…" instead of the date/place label, and returns to the SMB photos as soon as a read succeeds. A share that answers but refuses or lacks every one of the 8 photos sampled at start (seen while the clone was refreshing) is treated the same way: retry, then stored artworks. A configuration error (Guest rejected, signing required, wrong share) shows an error message instead and does not retry. Photos are removed from the session pool only for per-photo errors, never for network errors.
5. Make the app the system screensaver so it starts on idle. On this TV, selection uses one-time `adb` setup; no separate TCL Auto Launch control was found or needed for observed idle activation (see [device testing](DEVICE_TESTING.md#setup-sequence)). Recheck after firmware updates.

## First build acceptance criteria

- App appears in the TV launcher and every control is usable with a D-pad and Select/Back.
- Local sample images display without stretching; landscape and portrait photos are handled gracefully.
- Interval survives app restart and the photo changes at the selected interval.
- Slideshow can run both from a launcher preview and from the `DreamService`.
- The dream stops timers and image work when dismissed.
- Actual TCL TV behavior is recorded: third-party dream selection uses `adb`, and the app started on idle at the default timeout without a separate Auto Launch setting. Recheck after firmware updates.

## Cloud source expectations

- Google Photos: standard Google sign-in plus the Picker API can access photos and videos the user explicitly selects. Google's purpose-built Ambient API supports TV slideshows and user-configured sources, but requires acceptance into the Photos partner program. Do not promise automatic sync of arbitrary existing albums through normal sign-in or the Picker API.
- Mac mini Photos library: the TV reads files from the library package over SMB, read-only. The SMB client must support an explicit Guest access mode for the tested share; Guest is distinct from anonymous access. The Mac mini's SMB server is configured not to require signing so that Guest sessions work; the user accepted unsigned sessions because the share is read-only and LAN-only. The app samples up to 1,000 supported images from the full tree per run and shuffles the selected pool. `originals` also contains hidden and recently deleted photos, and its files do not include edits made in Photos (see [what originals contains](PHOTO_SOURCES.md#what-originals-contains)). Phase 1 album selection covers regular user-created albums through a metadata-only index to existing files. Shared Albums are deferred to a later phase while their storage mapping is investigated. Package-internal directories are not themselves albums.
- A source must clearly show when selection expires, is unavailable, or requires renewed permission. Avoid a silent empty slideshow.

## Open product decisions

- The TV is a TCL 65" A300 (NXTFRAME) on Android TV 12 (see [known TV facts](DEVICE_TESTING.md#known-tv-facts)). Current firmware testing found that TCL Art Mode did not interrupt a manually started artwork or the app DreamService. Recheck after firmware updates.
- Default SMB source is `Photos Library.photoslibrary/originals`. The user accepts that it can include hidden and recently deleted photos, and does not want a separate warning or opt-in. Originals are unedited. The current album-selection plan uses an index to point at existing originals rather than exported photo copies.
- **Decision (2026-10-13): make photo originals readable by Guest at the storage layer.** Many originals in the live library are owner-only (0600), and Carbon Copy Cloner copies those modes to the shared clone, where SMB Guest is denied. Using `tools/smb_access_probe/make_photos_readable.sh`, the user added group/other read to supported photo files (jpg, jpeg, png, webp, heic, heif) below the live library's `originals`; nothing else in the package is touched. The next CCC run propagated the change. The user runs the permission script manually once a day before the daily clone, so new photos become readable on the next refresh; automation beyond this routine is deferred. Accepted consequence: any account on the Mac mini, and any device on the LAN that can reach the Guest share, can read every photo, including hidden and recently deleted ones. Alternatives that were considered and not chosen: a Samba `force user` share, a Mac-side photo service running as the owner, or an export folder.
- **Decision (2026-10-17): extend the readable-by-Guest change to videos.** At the user's request, `tools/smb_access_probe/make_photos_readable.sh` now also adds group/other read to video originals below the live library's `originals` (mov, mp4, m4v, 3gp, 3g2, avi, mpg, mpeg, mts, m2ts), including the short motion clips Photos keeps beside Live Photos. Reason: the media-type feature needs the TV to play videos, and in a 28-video sample only 8 were readable by Guest (every clip above 18.4 Mbps was owner-only; see [photo sources](PHOTO_SOURCES.md#video-permissions-2026-10-17)). The routine is unchanged: run the script on the live library, then the daily CCC clone. Accepted consequence, as for photos: any account on the Mac mini and any device on the LAN that can reach the Guest share can read every video, including recently deleted ones. `INCLUDE_VIDEOS=0` restores photos-only runs, and `revert` undoes every recorded path.
- **Decision (2026-10-17): the screensaver does not play videos.** Videos are for the in-app slideshow only. When the in-app Type setting includes videos, the DreamService shows 500 random photos from the library instead (details in [media type](MEDIA_TYPE.md#screensaver)).
- **Decision (2026-10-18): the slideshow never shows screenshots, documents, or receipts.** Applies to the in-app slideshow and the screensaver, in *All* and *Choose Albums*, as Photos classified them: the screenshot flag, document confidence of 0.4 or more, or receipt confidence of 0.19 or more (9.4% of the library on the 2026-10-06 snapshot). Photos not yet analyzed by Photos, and photos newer than the TV catalog, are not filtered until the catalog is refreshed; with no usable catalog nothing is filtered. ID cards and real documents scored below 0.4 can still appear, and a few ordinary photos at 0.4 to 0.6 are hidden. Evidence and thresholds: [photo sources](PHOTO_SOURCES.md#excluding-screenshots-documents-and-receipts-2026-10-18).
- **Decision (2026-10-18): portrait pairs.** A **Layout** setting, **Single** (default) or **Portrait pairs**, applies to the in-app slideshow and the screensaver. In Portrait pairs two portrait photos can share one slide, side by side at full height and never cropped, over a pinstripe, diamond lattice, walnut frame, or brass fillet mat background (never the same style twice in a row); landscape photos and videos stay as they are and a lone portrait stays on black. About 60% of portraits are paired (a constant, not a setting). A pair stays up for one Interval. Needs catalog version 5. Details in [multi-image layouts](MULTI_IMAGE.md).
- Phase 1 album selection covers regular user-created albums. Use a read-only metadata index; do not present package-internal directories as albums. Shared Albums created by the user or shared with the user are a later feature, contingent on verifying their storage mapping.
- Phase 1 cache decision: use the Photos database album UUID (`ZUUID`) as the opaque ID and build a versioned JSON catalog in persistent app-private TV storage from a locally staged read-only SQLite snapshot. The user can explicitly refresh it; cache loss triggers a rebuild. Full clone mapping validation is recorded in [photo-source findings](PHOTO_SOURCES.md#phase-1-regular-album-cache). This private Photos schema can change, and CCC UUID continuity has not yet been verified across a refresh.
- Confirm that the daily CCC clone remains complete relative to the live library; full content equality has not been verified. Photos is set to "Download Originals to this Mac".
- Whether display images should be cached on the TV for offline playback, and for how long.
